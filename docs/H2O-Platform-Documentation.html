1. Executive Summary

1.1 Platform Overview

H2O Online is a comprehensive water delivery and hydration management platform designed to connect customers, water suppliers, and delivery partners through a unified digital ecosystem. The platform enables on-demand water ordering, subscription-based recurring deliveries, wallet-based payments, real-time order tracking, supplier fulfillment management, delivery partner logistics, and centralized admin oversight.

The platform consists of three integrated components:

  • Mobile App — React Native (Expo) application for customers, suppliers, and delivery partners
  • Admin Portal — React web application for platform administrators and sub-admins
  • Backend API — Node.js / Express REST API with MongoDB database
Mission: Deliver clean, reliable water to homes and businesses while giving suppliers and delivery partners the tools to manage orders, earnings, and operations efficiently — all under one admin-controlled marketplace.

2.2 Data Flow

  1. Mobile and admin clients authenticate via JWT tokens
  2. API requests are routed through Express middleware (auth, adminAuth)
  3. Business logic in route handlers and services (e.g., order payout)
  4. Mongoose models persist data to MongoDB
  5. Wallet transactions update balances atomically on order placement and delivery

7. Core Business Workflows

7.1 Instant Order Lifecycle

1. Order Placement — Customer selects products, checkout, pays (wallet/COD). Stock validated. Wallet debited → platform wallet credited.
↓
2. Supplier Notification — Order created with supplierResponses[] per unique supplier (status: pending).
↓
3. Supplier Action — Accept (ETA + assign rider) or Reject. All reject → order cancelled.
↓
4. Pickup — Delivery partner marks picked up. Status: picked_up.
↓
5. Delivery — Partner marks delivered. Order status: delivered.
↓
6. Payout — Platform wallet debited. Supplier gets (100−commission%) of items. Delivery partner gets 10% of total.

7.2 Subscription Lifecycle

1. Creation — Customer selects plan, products, frequency, dates, time window, address.
↓
2. Admin Assignment — Admin assigns delivery partner + pickup hub. Bulk assign with slot conflict checks.
↓
3. Recurring Delivery — Partner fulfills on schedule via Subscription Orders screen.
↓
4. Monthly Billing — Auto-generated bill (due 5th). Customer pays via wallet.
↓
5. Management — Admin can pause, cancel, or delete. Customer can cancel via app.

7.5 Support Communication Workflow

  1. Supplier or delivery partner opens support screen on mobile
  2. Sends message via API → stored in support thread
  3. Admin sees new thread/message in admin portal support module
  4. Admin replies → message delivered to mobile on next poll (5-second interval)
  5. Bi-directional conversation until issue resolved
